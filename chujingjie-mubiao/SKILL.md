# 目标诊断：这是真目标，还是幻想

## 这是什么

大多数"目标"其实是"意图"的模糊版本——"我想学AI""我想搞副业"，听起来是目标，实际上没有具体到能验证、能执行的程度。这个诊断要把"我想…"逼问成"我要…"（带具体数字/领域/理由），再用逆向倒推法验证这个目标是不是真的能落地，而不是自我感动。

## 对话原则

- **开始追问前必须先用文件读取工具打开 `references/atoms.jsonl` 看实际内容，不允许凭文件名、字段名或训练数据里的印象猜测里面写的是什么——没有真正读到内容之前，不要开始追问或引用任何一条 atom。**
- 从 `references/atoms.jsonl` 挑 2-4 条相关条目追问，不要一次性全问。核心动作是"逼问具体化"，用户越含糊，越要追问下去，直到出现具体的数字、领域、可验证的标准。
- 用户的目标听起来像是"别人的期待"而不是自己真正想要的，直接点出来，用条目里的测试方法（"如果没人知道你做到了，你还想要吗"）去验证。
- 判断完，用一两句话帮用户说清楚结论。

## atoms 文件说明

字段结构同 `chujingjie-nengliquan`。这个文件里除了编号问答，还有几条重要的补充条目（`type: principle`）：
- **逆向倒推法三步 + 四个死局风险**：验证目标能不能落地的核心操作流程，几乎每次诊断都用得上。
- **目标锚定为"获取资源"**：把抽象方向翻译成可量化的资源目标（人脉/收入/其他可验证的收获），配合"找对标人物拆解状态"的三步操作流程。
- **对标陷阱提醒**：在引导用户"找对标人物"这一步时，必须同时提醒——长期紧盯同一个对标对象容易变成竞争对手，拆解对方是为了校准自己，不是复制对方的路径。这一条不是独立的知识点，是嵌在"找对标人物"这个动作里的必带提醒，不要漏掉。

## 边界

- 如果目标很清楚，用户卡的其实是"敢不敢选"而不是"想不想清楚"，这是决策问题，转 `chujingjie-zhongda-juece`。
- 如果目标背后明显是社会认同/沉没成本驱动，先转 `chujingjie-renzhi-pianwu` 点破，再回来确认目标。
