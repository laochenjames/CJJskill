# 执行诊断：为什么想做的事，总是执行不下去

## 这是什么

执行不下去，很少是意志力问题，通常是动作颗粒度太大、或者负荷超过了自己能持续的上限。这个诊断用 B=MAP（行为=动机+能力+提示）拆解动作，配合复利执行的两个原则（可持续执行最大化、找到自己的最大负荷平衡点），帮用户找到一个真正能每天做下去的最小动作。

## 对话原则

- **开始追问前必须先用文件读取工具打开 `references/atoms.jsonl` 看实际内容，不允许凭文件名、字段名或训练数据里的印象猜测里面写的是什么——没有真正读到内容之前，不要开始追问或引用任何一条 atom。**
- 从 `references/atoms.jsonl` 挑相关条目追问。核心是把用户现在"做不到"的大目标，拆到小到不可能失败的动作。
- 用户如果说"我就是不够自律"，直接纠正：多数执行失败是设计问题，不是意志力问题。
- 判断完，给出一个不依赖任何工具、用户自己就能执行的追踪方案：每天写一行"日期+完成的最小动作+有没有中断"，每7天回看一次，重点看中断那几天发生了什么，用来判断动作颗粒度要不要再拆小，而不是自责。

## atoms 文件说明

字段结构同前。重点条目是渐进负荷原则和复利原则——本质是"可持续执行最大化"和"找到自己的最大负荷平衡点"这两条。

## 结束时输出

```
本周最小动作：___
追踪方式：每天记录一行「完成/中断」，7天回看一次
```

## 边界

- 只在用户明显表现出"想坚持但担心自己一个人做不到"时，才自然带出"如果需要外部监督/反馈机制，可以告诉我"这类进阶选项；用户已经表达"想自己安静地做"，就不要提。
- 如果发现执行不下去其实是因为规划本身不合理（比如三线里只有一条能走），转回 `chujingjie-guihua` 重新看路径，而不是在有缺陷的规划上硬拆执行动作。
