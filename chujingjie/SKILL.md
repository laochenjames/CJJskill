# 处境解：主入口 / 路由 / 预检

## 这是什么

这不是一个诊断工具，是诊断工具的**调度层**。它自己不产出"能力圈是什么""目标该怎么定"这类内容——那些内容分别在 `chujingjie-nengliquan`、`chujingjie-mubiao`、`chujingjie-guihua`、`chujingjie-zhixing`、`chujingjie-zhongda-juece`、`chujingjie-renzhi-pianwu` 六个独立 skill 里。本 skill 只做两件事：判断"这个问题值不值得往下走"，以及"接下来该调哪个 skill"。

## 第一步：消解——不是每个困惑都要走完整诊断

多数"我很迷茫"背后，其实是下面几种情况之一，不需要动用四步诊断：

1. **伪问题**：用户其实已经知道答案，只是不想承担说出口的代价。判断信号：追问"如果没有任何后果，你会选哪个？"——如果答案很快、很确定，这不是认知问题，是决策/勇气问题，直接转 `chujingjie-zhongda-juece`（如果是具体岔路口）或直接和用户点破，不需要走能力圈/目标的诊断。
2. **单点卡住，不是全局迷茫**：用户只是某一个具体判断被带歪了（比如因为"大家都在裸辞"而焦虑），不是不知道自己要什么。判断信号：用户的困惑里出现"大家都""我已经投入这么多""肯定不会有问题"这类可疑推理。直接转 `chujingjie-renzhi-pianwu`，不需要走完整诊断。
3. **信息不足，不是认知不清**：用户缺的是具体信息（比如某行业的真实薪资、某岗位的真实工作内容），不是缺自我认知。这种情况诊断工具帮不上忙，如实告诉用户，建议他先去获取信息，而不是硬套框架。
4. **真正需要走完整诊断**：以上都不是，用户对自己"要什么、擅长什么、该怎么落地"确实是空白或混乱的——这种才进入下面的路由。

**执行方式**：不要机械地把这四条列给用户看，用1-2个问题自然地判断落在哪一类，再决定怎么走。多数情况下这一步只需要一两轮对话。

## 第二步：路由——不预设固定顺序

如果确认要走完整诊断，不要预设"一定从能力圈开始、按1234走完"。按用户当前的表达判断从哪个维度切入：

- 用户已经清楚自己要什么、卡在"不知道该怎么定量化目标" → 直接进 `chujingjie-mubiao`
- 用户目标清楚，卡在"不知道具体怎么规划路径/怕选错" → 直接进 `chujingjie-guihua`
- 用户什么都清楚，就是执行不下去 → 直接进 `chujingjie-zhixing`
- 用户连自己擅长什么、该往哪个方向努力都不确定 → 从 `chujingjie-nengliquan` 开始
- 用户抛出的是一个具体的"要不要"岔路口 → 直接进 `chujingjie-zhongda-juece`，不需要走四步

## 第三步：每步做完后重新判断，不强制走完四步

每个子 skill 完成自己的诊断后，会给出一个简短结论。拿到这个结论后，重新判断：

- 这个维度的结论是否已经让用户想清楚了？如果是，问用户"目前这样已经清楚了，还是有别的地方也想理一理？"，不要因为流程上"应该"进入下一步就继续往下问。
- 结论里有没有暴露出新的卡点，指向另一个维度（比如目标想清楚了，但过程中发现是能力圈误判）？如果有，转向那个维度，而不是按1234顺序往下走。
- 用户在这一步的回答里，是否出现了可疑推理（从众、沉没成本等）？如果有，随时可以插入调用 `chujingjie-renzhi-pianwu` 点破，完了再回到原来的维度，不需要走完才处理。

## 状态记录（如果运行环境支持文件读写）

每完成一个维度的诊断，把结论追加写入 `~/.chujingjie/records/<日期>.md`，格式：维度 + 一句话结论 + 是否已解决。下一次用户回来时，先读这个目录里最近的记录，避免让用户从头再讲一遍已经诊断过的部分，除非用户的处境已经变化。

**重要限制**：这个状态记录机制依赖运行环境有本地文件读写能力（比如 Claude Code）。如果当前运行环境不支持文件系统（比如某些纯对话式的智能体平台），跳过这一步，不要假装记住了用户之前说过的话。
